浏览器翻译与本地翻译实施路线图

> **状态（2026-10-17 更新）**：本文为 2026-10-10 的历史路线图存档。当前实现已收敛为“扩展 + 云端字幕服务（方案 A）+ 独立本地服务”：本地接入模式已移除，方案 B（浏览器端 WASM ASR）仍未实施。当前行为以 [README](../README.md)、[TUTORIAL](./TUTORIAL.md)、[PLAN_B_BROWSER_WASM_ASR](./PLAN_B_BROWSER_WASM_ASR.md) 为准。

日期：2026-10-10。版本：v0.3，覆盖完整产品目标与通用 API 接入。

依据：[技术调研](./browser-translation-research-2026-10-10.md)及已确认的产品范围。本文件更新原有范围和实施顺序，API 对接细节见[通用接入方案](./browser-translation-api-integration-2026-10-10.md)。已有资料调研仍可复用，原有“有限网页 MVP”不代表完整产品。本轮只更新文档，尚未搭建工程、安装依赖、下载模型或执行功能与性能实测。

已确认的必备目标包括：本地文件翻译、离线翻译、多种形式的网页翻译、已有字幕的视频翻译、无字幕视频的语音识别与双语字幕，以及 AI 翻译。上述能力均进入最终验收。阶段交付可以先完成其中一部分，完整产品必须覆盖全部必备目标。

以下清单把“各种翻译”转为可开发范围。其中具体格式、首批网站与语言覆盖属于建议基线，在 P0 固定样本和支持矩阵；不能将功能种类齐全解释为任意网站、格式和语言均已兼容。

| 能力 | 建议的完整产品范围 | 必达阶段 |
| --- | --- | --- |
| 网页文字 | 整页双语/译文显示与恢复、划词、悬浮或选区翻译、用户主动触发的输入翻译、站点设置；动态页面与复杂 DOM 适配 | P2 |
| 网页图文 | 网页图片/截图 OCR 翻译、网页 PDF 的导入与阅读翻译 | P3 |
| 本地文件 | TXT/Markdown、DOCX、文本 PDF、扫描 PDF、PNG/JPEG 图片、SRT/VTT 字幕；导入、提取、对照阅读及约定格式导出 | P3 |
| 已有字幕视频 | 网页字幕轨/站点字幕及本地字幕文件的翻译、双语显示、时间轴保持和字幕导出 | P4 |
| 无字幕视频 | 本地视频与网页播放音频的语音识别、时间戳生成、AI 翻译及双语字幕 | P5 |
| 离线处理 | 资源准备后，约定文件、已加载网页和本地视频的 OCR/ASR/翻译可在本机完成 | P1 建基础，P6 完整验收 |
| AI 翻译 | 本地 AI 翻译接入统一接口；推荐同时接入一个用户自带凭据的云端 AI 服务，供用户选择 | P1 建基础，P2–P5 共用 |

配音、声音克隆、直播、多端同步、账号计费和复杂文档的像素级排版复刻可以后续增加；它们不取代上表中的必备项。视频基础验收覆盖点播；直播需另定持续流与延迟指标。

离线模式的定义是：运行时、翻译模型、OCR/ASR 模型及语言资源完成下载或离线导入后，在约定硬件和语言范围内断开外网，仍能完成对应处理。离线模式不自动调用云端、不静默降级为云端识别或翻译；缺少资源时明确提示准备资源或由用户主动切换模式。在线网页和在线视频本身的获取可能仍要联网，应与翻译计算是否本地区分。

建议采用“浏览器扩展 + 可替换的处理服务 + 统一任务/翻译接口”。处理服务可以来自本地伴随服务、用户已经部署的本机/内网 API 或受控网关；优先复用已有模型服务，补充缺少的文件、OCR、ASR 和长任务能力。纯文本 API 接入不要求另外安装同一推理引擎。完整离线目标仍需实际具备本地处理能力并准备资源，但不限定必须使用本项目重新封装的同一套程序；自建云端服务器仍非必要。

API 接入将部署位置、请求协议、实际处理位置和服务能力分别配置。支持云端直连、本机/内网 API 与用户自建转发网关；协议通过 OpenAI Responses、Chat Completions 兼容、Ollama 原生、专用翻译 JSON 等适配器区分。网关对外协议与上游部署位置相互独立，本地网关转发云端不能算作本地推理。当前尚未选定实际供应商，配置与验收按通用接入方案执行。

| 技术层 | 建议基线 | 状态 |
| --- | --- | --- |
| 扩展 | 桌面 Chrome / Edge，Manifest V3 + WXT + TypeScript | 沿用现有推荐 |
| 前端 | React 扩展页面；普通 TypeScript 网页引擎；文件工作台和字幕 UI 放在扩展页面或内容脚本中 | 推荐方案 |
| 扩展后台 | Service Worker 管理权限、会话、配置、短任务路由和扩展缓存 | 推荐方案 |
| 媒体上下文 | offscreen 文档处理标签页媒体流；页面侧维护播放器身份和媒体时间 | 需 P0 验证 |
| 本地服务 | 优先验证 Windows；复用兼容的既有服务，或用伴随服务提供缺少的处理能力 | 自建时语言、框架和发行方式在 P0 后锁定 |
| 本地 AI | 优先复用用户部署的 API；Ollama 等为候选，具体模型按语言、资源、质量和许可选择 | 未连接实际服务、未安装、未选定权重 |
| 本地 ASR | whisper.cpp 为优先验证候选；OCR 使用独立适配器 | 未安装、未做速度和准确率验证 |
| 云端 AI | 至少一个 BYOK 适配器作为推荐接入路径；专用翻译 API 可另行接入 | 供应商、认证和费用待核实 |
| 状态与存储 | 扩展 IndexedDB 保存扩展侧缓存；本地服务保存文件、长任务检查点和本地缓存 | 格式、容量与清理策略待设计 |

浏览器内的 Translator API 可以作为轻量本地翻译适配器，但不能承担全部离线功能。官方要求检查语言可用性、处理初次资源下载及用户激活，而且该 API 不支持 Web Workers；实际扩展调用上下文需验证。[Chrome Translator API](https://developer.chrome.com/docs/ai/translator-api)

Ollama 同时提供本地与云端能力，因此连接 localhost 本身不能证明离线。离线模式要验证使用已下载的本地模型并关闭云端回退。[Ollama API](https://docs.ollama.com/api/introduction)、[Ollama FAQ](https://docs.ollama.com/faq)

整体职责与数据流如下：

~~~mermaid
flowchart TD
  W[网页文字与图像] --> E[浏览器扩展：提取、交互与渲染]
  F[用户选择的本地文件] --> UI[扩展文件工作台]
  V[网页视频与字幕] --> E
  V --> O[offscreen：用户触发的音频采集]
  E <--> B[扩展后台：权限、会话与任务路由]
  UI <--> B
  B <-->|配对后的本地接口| L[本地服务：解析、OCR、ASR与长任务]
  UI -->|文件流或分块| L
  O -->|带时间信息的音频块| L
  B --> T[统一翻译契约与适配器]
  L --> T
  T --> LOCAL[本地 AI / 本地翻译引擎]
  T --> CLOUD[用户选择的云端 AI / 翻译 API]
  L --> OUT[文档结果、双语字幕与导出]
  OUT --> UI
  OUT --> E
~~~

图中的统一接口表示共享的任务、结果和能力契约，可以有不同执行环境。每项任务指定唯一执行者：扩展侧管理页面短任务，本地服务管理文件与媒体长任务；同一任务不能在两侧分别自动重试并重复执行。

| 开发范围 | 主要职责 |
| --- | --- |
| 前端 | 网页提取与渲染、弹窗和设置、划词/输入交互、文件导入与对照阅读、播放器字幕、引擎选择和任务进度 |
| 扩展后台 | 浏览器权限、消息来源校验、页面会话、服务配置、请求路由、短任务去重与缓存、与本地服务配对 |
| 本地服务 | 文件解析/导出、OCR、音视频解码、语音识别、本地推理、资源准备、持久任务、取消恢复与资源调度 |
| 共享协议 | 翻译单元、资产与任务引用、能力声明、错误码、进度事件、结果版本和导出格式 |

因此开发仍可按前端和后台两个方向推进，后台方向同时包含扩展后台和本地服务。共享协议、工程配置与依赖集中维护。规划目录如下，当前尚未创建：

~~~text
apps/extension/           WXT 扩展、网页引擎、文件工作台、播放器与字幕 UI
services/local/          本地任务、文件/OCR/ASR、推理适配、资源管理
contracts/               跨语言任务、翻译、能力与错误契约
tests/fixtures/          固定网页、文档、图像和视频样本
~~~

先固定接口再并行实现。翻译单元至少包括来源类型、任务/资源 ID、单元 ID、原文摘要、修订号、语言对和文本；不同来源保留各自的定位信息：

| 来源 | 必须保留的定位信息 | 呈现方式 |
| --- | --- | --- |
| 网页 | 页面会话、节点映射、原文版本；DOM 引用留在 Content Script | 原节点保留，新增或移除独立译文 |
| 文档/图片 | 文件版本、页码、块 ID、阅读顺序、必要的版面坐标 | 对照阅读、局部覆盖或约定格式导出 |
| 视频/字幕 | 媒体 ID、会话代次、cue ID、起止时间、字幕修订号 | 按媒体时间显示和导出字幕 |

OCR、ASR 和翻译分别实现能力适配器。翻译接口接收文本与上下文，返回按单元 ID 对齐的译文；OCR 返回文本与坐标，ASR 返回文本与时间戳。AI 翻译不自行生成文件定位或改写字幕时间戳。各语言能力分别声明，当前任务采用能够组合成立的语言路径。

凭据、原始文件和媒体数据不进入普通网页消息。大文件与音频采用流式或分块传输，控制消息只传任务和资源引用。本地接口建议只监听回环地址，具有配对鉴权、来源检查和固定能力端点；不能暴露任意文件读取或通用执行接口。Native Messaging 可用于发现和启动已安装的本地程序，但其 JSON 消息有大小限制，媒体数据需另外设计传输路径。[Chrome Native Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging)

三类输入共用翻译接口，但各自保留处理管线：

1. **网页**：正文/选区/主动提交的输入 → 提取与分段 → 可视优先队列 → 翻译 → 版本校验 → 双语呈现或输入替换。自动提取默认排除表单和编辑器，输入翻译只处理用户主动提交的内容。站点规则、iframe 与 Shadow DOM 支持范围进入测试矩阵；PDF 和图片转入相应文件/OCR 管线。
2. **文件与图片**：用户导入 → 格式解析或 OCR → 阅读顺序与保护片段整理 → 翻译 → 对照阅读及导出。文本 PDF 与扫描 PDF 分开处理；DOCX 以段落/表格结构与基本样式为验收基线。PDF 首先保证内容、阅读顺序和对照阅读，固定版式原样重排不作为“支持 PDF”的默认承诺。字幕文件按 cue 解析和回写，不能当普通长文本丢弃时间轴。
3. **视频**：已有字幕时走字幕提取/导入 → 上下文整理 → 翻译 → 时间轴保持 → 双语字幕；无字幕时增加音频获取 → 解码/分段 → ASR → 带时间戳原文，再接入同一翻译与字幕链路。本地文件可先处理再播放，网页音频采用用户触发的采集方式。

Chrome 官方提供 Service Worker 取得 tabCapture 流标识、交给 offscreen 消费的实现路径，跨上下文使用从 Chrome 116 起支持。采集必须由用户主动触发，并需要将音频接回输出以保持原视频声音；不能依赖 Service Worker 一直运行来维持采集。[官方采集说明](https://developer.chrome.com/docs/extensions/how-to/web-platform/screen-capture)、[tabCapture](https://developer.chrome.com/docs/extensions/reference/api/tabCapture)、[offscreen](https://developer.chrome.com/docs/extensions/reference/api/offscreen)

字幕按播放器媒体时间显示。暂停、跳转、倍速、全屏、广告或换集都要处理；跳转和媒体切换提升会话代次、清理旧音频与字幕任务。倍速变化需要音频时间与媒体时间的映射，不能仅用系统时钟累加。长视频采用分块、检查点和有上限的队列。

无字幕网页视频实时识别只能处理已经播放的声音，必然有断句、识别与翻译延迟。本地文件预处理后的字幕可以与播放同步。实时延迟、可支持倍速及实时性是否达标，需要在目标硬件上测量，不能直接从推理库示例推导。[whisper.cpp 官方项目](https://github.com/ggml-org/whisper.cpp)

视频兼容性以支持矩阵验收，先覆盖标准 HTML5 视频和选定站点，再扩大站点适配。受保护媒体、无法访问的字幕轨、自定义播放器和同一标签页多个声源可能需要降级提示；“视频翻译”不等于已验证全部视频站点。

实施路线将高风险的本地推理、文件解析和视频采集放到早期验证，随后逐步完成产品能力。下表所有阶段均待执行。

| 阶段 | 主要交付 | 通过条件 |
| --- | --- | --- |
| P0：范围与技术验证 | 固定格式/语言/网站/硬件样本；确定 API 配置、协议、能力与鉴权契约；验证本地 AI、单页 OCR、短视频 ASR、音频采集和本地连接；判断既有服务可复用范围 | 断网 TXT 翻译和短视频识别→翻译可跑通；浏览器采集有声音且可停止；记录质量、耗时、内存和安装条件 |
| P1：统一基础 | 扩展工程、可替换的本地任务服务、文件工作台、服务配置、配对、能力发现及资源管理；实现本地与选定云端/网关协议适配 | 同一批文本可沿统一契约处理；不同服务按协议解析；离线模式无外部推理或静默回退；任务、错误、取消与结果版本契约稳定 |
| P2：网页文字 | 整页/划词/悬浮或选区/输入翻译、恢复、站点设置；动态 DOM、队列、缓存、iframe/Shadow DOM 的约定覆盖 | 固定页面无陈旧回填、译文回环或交互损坏；支持本地 AI 翻译；站点规则与授权行为可解释 |
| P3：文件与网页图文 | TXT/Markdown、DOCX、文本 PDF、扫描 PDF/图片 OCR、SRT/VTT；网页 PDF/图片的处理入口；对照阅读和导出 | 每个约定格式至少有成功、异常和结构复杂样本；OCR→翻译能离线运行；阅读顺序与导出结构符合约定 |
| P4：已有字幕视频 | 网页字幕轨与首批站点适配、本地字幕导入、双语字幕、样式、同步和导出 | 本地和网页两种入口均通过；暂停、跳转、倍速、全屏和换集不串字幕，原时间轴保持 |
| P5：无字幕视频 | 本地视频解码/ASR；网页标签页音频采集/分段 ASR；AI 翻译、字幕展示、分块恢复与导出 | 两种入口均通过；本地视频可断网完成 ASR→翻译→字幕；网页采集不破坏原音，停止即释放，记录字幕延迟与识别质量 |
| P6：完整产品验收 | 安装与资源准备、离线完整链路、硬件和语言矩阵、Chrome/Edge 回归、失败恢复、清理与打包 | 用户确认的全部必备项通过；交付可安装扩展、本地服务或兼容后端接入方式、资源准备说明、测试记录和已知限制 |

P2 或 P3 的中间版本可以用于体验验证，不能标为完整目标已完成。文件和视频模块可在 P1 契约固定后并行开发，但最终必须回到同一能力、任务和错误协议集成。前端可以用模拟结果先完成交互；模拟通过不代表真实 OCR、ASR 或翻译通过。

最终验收至少包含以下交叉检查：

- 网页、文件、已有字幕视频、无字幕视频均能使用本地 AI 翻译；按推荐范围接入的云端 AI 同样走统一接口。
- 资源准备完成后，断开外网完成本地文件、图片/扫描 PDF、字幕及本地视频的处理；已加载网页的翻译不依赖云端。明确记录所用语言、模型和硬件。
- 视频覆盖“网页/本地 × 已有字幕/无字幕”四种组合，并分别记录暂停、跳转、倍速、全屏、长视频和中断恢复结果。
- 页面结果以节点/原文/会话版本校验；文件结果以资源版本校验；字幕结果以媒体和会话代次校验。取消后不得写入旧结果，共享请求按订阅者取消。
- 成功结果才进入缓存，缓存键包含引擎、模型、语言对、源文本、上下文和策略版本；本地长任务有检查点。未知状态的云请求不无条件重放。
- 分别评估翻译质量、OCR 阅读顺序与识别准确性、ASR 错误和字幕对齐；记录首屏耗时、文档吞吐、字幕延迟、内存/GPU 占用及外部调用量。
- 浏览器后台休眠、本地服务退出、模型缺失、内存不足、断流和权限拒绝都有可操作的状态与恢复路径。
