浏览器翻译插件 API 通用接入方案

日期：2026-10-10。版本：v0.1 设计方案。
关联：[总体路线图](./browser-translation-roadmap-2026-10-10.md)。

本方案覆盖云端 API、本机模型 API、局域网服务和用户自建转发网关。当前尚未指定实际服务商或协议，因此先固定通用接入边界；本文中的地址、模型 ID、字段和自定义端点均为设计示例，未创建接口、启动服务或执行真实调用。

统一原则是“按接口与能力接入”。模型已经部署并提供 API 时，可以复用该服务；本地伴随服务补充尚缺少的文件解析、OCR、ASR 与长任务能力，也可以由兼容的现有后端承担。单纯调用模型 API 不要求另外部署同一模型。API 接入不取消既定的离线、文件和视频目标。

需要分开描述四件事：

| 维度 | 例子 | 对接入的影响 |
| --- | --- | --- |
| 接口部署位置 | 本机回环、局域网、公网 | 决定地址、访问权限和连接方式 |
| 接口协议 | OpenAI Responses、Chat Completions 兼容、Ollama 原生、自定义 JSON | 决定请求、返回、流式事件和错误解析 |
| 实际处理位置 | 本机、内网设备、云端、未知 | 决定数据去向和离线资格；不能仅从 API 地址推断 |
| 服务能力 | 文本翻译、OCR、ASR、字幕时间戳、异步任务 | 决定能参与哪些产品流程 |

“转发网关”是部署与路由方式，不是一种固定请求协议。同一网关可以对外提供 Chat Completions 兼容接口，也可以提供专用翻译接口。

~~~mermaid
flowchart LR
  U[网页、文件与视频入口] --> R[任务路由与能力选择]
  R --> A[协议适配层]
  A --> C[云端供应商 API]
  A --> L[本机或局域网 API]
  A --> G[用户自建网关]
  G --> GL[本地或内网模型]
  G --> GC[云端上游]
~~~

常见部署方式如下：

| 使用方式 | 插件配置 | 额外要求 |
| --- | --- | --- |
| 直接调用云 API | 供应商协议、API 根地址、模型/引擎 ID、用户凭据 | 核验供应商认证、浏览器访问与使用条件 |
| 本机部署并封装 API | 回环地址、对外协议、模型 ID、服务要求的鉴权 | 浏览器所在机器能够访问该服务；无需重复部署推理引擎 |
| 局域网设备部署 | 实际设备地址或域名、协议、模型 ID、鉴权 | 使用可达地址；localhost 指浏览器这台机器，不能代指另一台服务器 |
| 自建转发网关 | 网关地址、网关协议、网关模型别名、网关访问令牌 | 网关自己管理上游模型地址、上游密钥、路由和限流 |

本地 API 转发到云端仍属于云端处理。本地文件通过云端 API 翻译，也不等于离线翻译。内网服务器可以做到无公网依赖，但应标为内网处理，不宣称内容只在用户设备上处理。离线资格结合已知服务配置和断外网验证确定，未知网关不能仅凭 localhost 或自报字段被认定为完全本地。

服务设置建议让用户填写名称、协议、API 根地址、模型/引擎、鉴权和用途；并发、超时、请求大小等放在高级设置。内部配置至少包含：

| 配置项 | 用途 |
| --- | --- |
| profileId / revision | 稳定标识服务配置，变更后隔离缓存与旧任务 |
| protocol / adapterId | 选择正确的请求与响应适配器 |
| baseUrl | 用户登记的 API 根路径；保留反向代理子路径和版本前缀 |
| auth / secretRef | 描述鉴权方式并引用受保护凭据；普通配置不携带明文密钥 |
| model / engine | 服务实际接受的 ID 或网关别名；允许手动填写，不强依赖模型列表接口 |
| capabilities | 声明并验证翻译、OCR、ASR、时间戳、流式、结构化输出和长任务等能力 |
| limits | 请求字符/字节或上下文上限、并发、超时与速率约束 |
| deployment / processingLocation | 分别记录接入位置与实际处理位置；保留未验证状态 |
| dataPolicy | 仅本机、允许内网、允许云端；禁止未授权的自动跨模式回退 |

这些是内部字段，并非要求所有供应商接受同样的 HTTP 参数。适配器只发送其接口实际支持的字段；数据策略由路由和可控服务共同执行。

本机兼容 API 的配置示意如下。它表示准备登记服务，不表示已经可用或已经通过离线验证：

~~~json
{
  "profileId": "my-local-ai",
  "revision": 1,
  "protocol": "openai-chat",
  "baseUrl": "http://127.0.0.1:8000/v1",
  "model": "your-served-model-id",
  "auth": {
    "type": "bearer",
    "secretRef": "local-ai-access-token"
  },
  "capabilities": {
    "textTranslation": true,
    "ocr": false,
    "asr": false
  },
  "processingLocation": "unverified",
  "dataPolicy": "device-only"
}
~~~

配置中的鉴权应与真实服务一致；不需要 token 的回环服务可使用专门的无鉴权配置。上述声明仍需连接与结果验证，“device-only”也必须在本机处理被确认后才能启用。

优先实现以下协议适配器，不把“兼容 OpenAI”当作所有功能通用的保证：

| 适配器 | 常见根路径与请求路径 | 适用范围 |
| --- | --- | --- |
| OpenAI Responses | 根路径含 /v1，请求 /responses | OpenAI 官方新接入的推荐路径，以及明确支持该接口的服务 |
| OpenAI Chat Completions 兼容 | 根路径含 /v1，请求 /chat/completions | 声明兼容的自部署引擎或中转服务；逐项验证参数和返回 |
| Ollama 原生 | 根路径含 /api，请求 /chat | 使用 Ollama 原生模型和生成选项 |
| 专用翻译 JSON | 本项目建议根路径含 /v1，请求 /translate | 自己封装面向翻译业务的服务 |
| 其他供应商/自定义适配器 | 由固定适配器定义 | 已有接口格式不同、使用专用认证或异步协议时 |

API 根路径与具体端点只拼接一次，例如 http://127.0.0.1:8000/v1 加 /chat/completions。不能重复补 /v1，也不能因绝对路径拼接丢掉网关前缀。高级自定义端点应有明确格式，不与根路径设置混用。

OpenAI Docs 明确区分 Chat Completions 的 messages/choices 与 Responses 的 input/output；两者的结构化输出参数和流式事件也不同。OpenAI 官方新项目推荐 Responses，但兼容服务需要按其声明选择，不能机械替换 URL。[OpenAI 官方迁移说明](https://developers.openai.com/api/docs/guides/migrate-to-responses)

Ollama 官方提供 http://localhost:11434/v1/ 的兼容入口，并说明只支持 OpenAI API 的一部分；本地示例中的 SDK API key 会被 Ollama 忽略，不能把任意占位字符串当作真实服务鉴权。[Ollama 兼容接口](https://docs.ollama.com/api/openai-compatibility) 原生 /api/chat 的返回和默认流式行为需要单独处理。[Ollama 原生 Chat API](https://docs.ollama.com/api/chat)

vLLM 官方提供兼容服务及 http://localhost:8000/v1 的示例。可用端点仍取决于所部署的版本、模型与配置，文本模型不因此自动具备语音识别能力。[vLLM 官方兼容服务](https://docs.vllm.ai/en/latest/serving/online_serving/openai_compatible_server/)

如果自行封装 API，可以选两种方案：

1. **对外兼容 Chat Completions 或 Responses。** 接受对应模型、消息/输入和生成参数，返回对应协议结构。插件里的翻译适配器负责生成翻译指令、组织段落 ID、解析译文和校验。适合希望同一服务还能供其他通用客户端使用的情况。
2. **对外提供专用翻译接口。** 接收源语言、目标语言、分段文本，直接返回对应译文；服务内部可调用任意本地或云端引擎。适合集中管理术语、提示词、批量、路由和翻译缓存的情况。

下面是本项目建议的专用契约，不是 OpenAI 的已有文本翻译端点，也不是已经实现的接口。

请求 POST /v1/translate：

~~~json
{
  "requestId": "request-example-1",
  "sourceLanguage": "en",
  "targetLanguage": "zh-CN",
  "segments": [
    { "id": "paragraph-1", "text": "Hello, world." }
  ]
}
~~~

成功响应：

~~~json
{
  "requestId": "request-example-1",
  "segments": [
    { "id": "paragraph-1", "translation": "你好，世界。" }
  ],
  "resolvedEngine": {
    "id": "configured-engine",
    "revision": "engine-config-1"
  }
}
~~~

至少要求段落 ID 不重复、不遗漏、不混入未知 ID；批量部分失败时逐段返回明确错误。文件坐标、网页节点和字幕时间轴由原始任务映射保留，翻译接口不自行更改它们。语言、占位符、长度及完成状态验证通过后才回填和缓存。通用生成式服务需要处理截断、拒绝、附加解释及无效结构；不支持结构化输出时，可以降为明确的一段一请求策略。

网关转发推荐分成两个独立认证边界：

~~~text
扩展或本地任务客户端
  └─ 使用网关令牌 → 你的网关
                        └─ 使用上游凭据 → 本地模型 / 内网模型 / 云服务
~~~

插件只保存访问网关所需的令牌。网关负责模型别名到上游的映射、鉴权、配额、并发、超时、响应转换和实际路由记录。上游地址来自已登记配置，不由网页通过翻译消息任意指定。网关令牌不是上游供应商密钥；跨域重定向不应携带原有认证信息。

产品公共上游密钥应保存在受控后端。个人 BYOK 根据供应商条件选择扩展可信上下文直连，或交给用户自己的本地服务/网关代发。OpenAI 官方建议 API 凭据保留在服务端，因此对其官方 API 优先采用本地服务或网关保管凭据。[OpenAI API 认证说明](https://developers.openai.com/api/reference/overview)

扩展中的请求放在具有对应 host permissions 的后台或扩展页面；Content Script 仅提交已登记的 profileId 与翻译数据。用户添加服务后申请对应域名权限，并在运行时校验地址、端口、协议和端点。host permissions 不是应用层鉴权，也不能代替服务自身的来源与访问控制。公网和内网连接优先 HTTPS，回环 HTTP 单独处理。[Chrome 扩展跨域请求](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests)

接入一个 API 只代表获得它实际提供的能力。完整产品需要分别配置以下接口，可由同一后端实现，也可由不同服务组合：

| 能力接口 | 输入与输出 | 负责场景 |
| --- | --- | --- |
| TranslationProvider | 文本单元 → 按 ID 对齐的译文 | 网页、文档、识别后的文本及字幕翻译 |
| OcrProvider | 图片/扫描页 → 文本、块坐标和阅读顺序 | 网页图片、本地图片、扫描 PDF |
| AsrProvider | 音频 → 带时间戳的原文和分段状态 | 无字幕网页与本地视频 |
| Document/Media Worker | 文件或媒体资源 → 文本块/音频片段/导出文件 | 格式解析、音频解码、重排及长任务 |

支持图片描述的通用视觉接口不一定能返回可靠 OCR 坐标；能转写音频的接口也不一定有字幕所需的时间戳或实时模式。必须分别验证，不能把一个 textTranslation=true 当作全部能力可用。

已有字幕只需翻译文本并保持时间轴；无字幕视频需要 ASR，再接翻译与字幕显示。可以组合“本地 ASR + 云端翻译”或“云端 ASR + 本地翻译”，但两者都不是完整离线处理。离线模式要求该任务实际使用的解析、OCR、ASR、翻译和资源均无外部依赖；仅声明支持本地 API 不足以通过验收。

网页短任务采用小批量请求；文件和视频长任务由唯一执行者管理。受控本地服务或网关可以额外实现 POST /v1/jobs、GET /v1/jobs/{id}、POST /v1/jobs/{id}/cancel 等异步契约，配合分块上传和进度事件。这些也是设计端点，不要求第三方模型 API 原生提供。

流式、错误和恢复按以下原则统一：

- 普通 HTTP JSON、SSE 和其他流式格式各自解析，转换成统一的进度/段落完成/任务完成/失败事件；不能用同一个字段路径解析全部服务。
- 只把完成且校验成功的译文视为最终结果；中途断流、截断、无效 JSON 不写入成功缓存。页面仍按原文与会话版本校验回填。
- 取消先令前端旧任务失效，再尽力取消排队/网络/后台计算；连接断开不保证远端停止推理或计费。
- 只有服务明确支持的幂等机制才能保证安全重试。客户端 requestId 本身不意味着远端去重，超时后的结果未知不能盲目重放。
- 缓存按服务配置、协议、模型、实际引擎/路由版本、语言、原文和翻译策略隔离。网关切换上游后更新路由版本或明确缓存策略，避免同名模型混用结果。
- 数据策略拒绝的云端回退必须终止任务并说明原因；不能用自动切换供应商掩盖本地服务不可用。

接入流程应为：新增服务 → 地址与权限检查 → 选择/填写模型 → 按能力发送固定的小样本 → 校验结果 → 保存配置。模型列表、健康检查或 capabilities 端点都不是所有服务的必选项；缺失时允许手动配置，但必须验证真实业务请求。测试使用固定公开短文本或用户明确选择的样本，不能自动读取当前网页或上传本地文件。

验证清单当前均未执行：

| 验证 | 完成条件 |
| --- | --- |
| 地址与协议 | 网关子路径、版本前缀和端点拼接正确；不同返回格式各自解析 |
| 鉴权与权限 | 错误令牌、权限拒绝和服务不可达可区分；日志与网页中不出现凭据 |
| 文本能力 | 真实短文本、分段 ID、占位符、截断与异常输出均有明确处理 |
| OCR/ASR | 所选服务确实提供必要坐标、阅读顺序或时间戳；不只验证模型可回答 |
| 网关 | 上游别名、认证、错误、取消、路由版本与数据策略按约定传播 |
| 离线 | 已准备资源后断外网验证；本机/内网位置记录准确，无静默云端回退 |
| 长任务 | 分块、中断、取消、恢复与缓存隔离正确；不重复启动同一任务 |

开发顺序：P0 固定配置、能力与协议契约并选定验证样本；P1 实现适配层，验证至少一条本地路径和选定的云端/网关路径；P2–P5 将网页、文件、OCR 和 ASR 接到同一能力体系；P6 做完整离线与跨入口验收。实际供应商和模型尚未确定，暂不承诺“填任意 API 地址即可兼容”。

当前产出仅为通用接入方案和配置示例，没有创建可运行服务、调用真实 API、保存任何密钥或进行联通性实测。
